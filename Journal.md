# Journal
Phase 1- ### Phase 1: The Core Gear (Leaf & Component)

In this phase, I created an abstract InventoryComponent class and an Item class that extends it so I can override the methods. Inside Main, I created two items using the constructor, an Iron Sword and a Health Potion. I used the methods to display each item's information and show their weights. The program ran successfully and displayed the correct information. InventoryComponent provides default implementations that throw UnsupportedOperationException because not every item or bag needs to use every method. For example, an individual item should not be able to add or remove other items, but a bag needs those operations. Default implementations allow subclasses to use the methods that make sense for them without being forced to implement methods they don't need. This design provides transparency for the client because it can interact with items and bags through the same parent type without needing to know all their internal details. Each class can handle its own operations while the client uses the common methods provided by InventoryComponent.

Phae 2 - 
In this phase, I created a Bag class that allows items and other bags to be added to it. The bag calculates its total weight by adding its own base weight to the weight of everything inside it. I tested it with an Iron Sword and a Health Potion, and the total weight came out to 4.8 lbs. The getWeight() method in Item returns the weight of that individual item. The getWeight() method in Bag uses a loop to go through its ArrayList and add the weight of each component to the bag's base weight. Polymorphism and recursion allow the bag to call each component's methods without needing separate code for items and other bags. If a component is an item, it returns its own weight. If a component is another bag, that bag calculates its own total weight, including its contents.
